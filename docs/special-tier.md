# 特別枠（901〜999）

## 特別枠とは

黒帯（301〜399）までは「AWSリソースの組み合わせ方を練習する」という閉じた世界の中で、[[difficulty-score]] の式に沿って難易度を設計できる。
しかし実務では、この式だけでは測れない・あるいは前提条件そのものが異なるお題が存在する。特別枠はそうしたお題を指す番号帯（901〜999）であり、
以下のいずれかの性質を持つものが対象となる。

1. **プライベートサブネット等の閉域網内で複数サービスを疎通させる必要があり、設定ミスがサイレント障害につながりやすいもの**
   ルートテーブル・NACL・セキュリティグループ・エンドポイントのいずれか一つの設定を誤っても、エラーメッセージが出ず「一部の経路だけ静かに塞がる」形で失敗する。
   このような失敗モードは、黒帯までのお題が前提とする「plan/applyが通れば大枠は動く」という感覚が通用しない。
2. **Terraform/HCLの外側に専用のCLI・SDK・Bundle形式（YAML等）が存在し、公式にも役割分担が推奨されているもの**
   例: Databricks（Databricks Asset Bundles）、Bedrock AgentCore（専用SDK/CLI）など。
   「プラットフォームレベルの基盤（VPC・IAM・ネットワーキングなど）はTerraformで、プロジェクトレベルの資材（ジョブ定義・エージェントロジックなど）は専用ツールで」という役割分担が公式にも推奨されており、
   Terraformだけで完結させようとすること自体が悪手になりうる。
3. **難易度スコアが33点を大きく超え、かつスコアが跳ね上がる主因がリソース数の多さではなく「配線（依存関係）の密度」であるもの**
   [[difficulty-score]] の式で言えば、Rの寄与よりも「深さ×3」「エッジ数×1」の寄与が支配的なケース。
   リソース数自体は黒帯と大差なくても、依存関係が密に絡み合うことで、設計判断の難易度が式の線形な増加以上に跳ね上がる。

## 特別枠SPEC.mdに必須の項目

通常のMust/Should/制約に加えて、特別枠のSPEC.mdには以下を必ず含めること。

- **Terraformと専用ツールの役割分担を受講者自身に判断させる設問**
  「なぜこの部分をTerraformで管理し、なぜこの部分は専用ツール（SDK/CLI/Bundle）に任せるべきか」を、正解を提示せずに問いの形で残す。
  受講者が自分で調べ、判断し、根拠を説明できることが目的であり、SPEC.md側で先に答えを書いてしまわない。
- **作業後は必ず `terraform destroy` する旨の注意書き**
  閉域網構成（NATゲートウェイ、VPCエンドポイント、プライベートサブネット内のマネージドサービスなど）は時間課金のリソースを含みやすく、
  放置すると通常のEC2 1台に比べて課金リスクが大きい。作業終了後・中断時は必ず破棄するよう明記する。

## 難易度スコアとの関係

特別枠のSPEC.mdにも、参考情報として [[difficulty-score]] の式によるスコアは算出・記載する。
ただし段位判定には使わず、「なぜこの式の想定を超えるのか」を一言添える（サイレント障害のリスク、専用ツールとの役割分担判断が必要、配線密度が主要因、など）。
