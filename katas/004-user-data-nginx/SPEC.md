# 004-user-data-nginx: user_dataでnginxを自動起動する

## 背景・目的

`003-security-group` で80番ポートを許可する土台ができた。本お題では、EC2インスタンス起動時にnginxを自動インストール・自動起動させ、実際にHTTPアクセスしてレスポンスが返ることを確認する。このお題で新しく学ぶ概念は「user_data」1つだけに絞る。

`003-security-group` の `terraform/` の中身をコピーし、EC2インスタンスの設定に `user_data` を追加する形で進めること。

## 登場する概念（詰まったら調べる）

- **user_data**: EC2インスタンスに「起動時に自動実行させたいコマンド」を渡す仕組み。EC2インスタンスを作るリソースの中に、シェルスクリプトの中身をそのまま設定できる項目がある。ここに「nginxをインストールして起動する」処理を書けば、インスタンス起動と同時にWebサーバーが立ち上がる。手動でSSHログインして設定する必要はない（そもそも本お題ではSSHを開放しないので、この方法以外にWebサーバーを起動する手段がない）。
- 使用するAMIによってパッケージ管理コマンドが異なる（Amazon Linux系なら `dnf`/`yum`、Ubuntu系なら `apt`）。`002-ec2-only` で選んだAMIに合わせたコマンドを調べること。minimal版のAMIを使っていないか、改めて確認するとよい。

## 進め方の手がかり

1. `003-security-group/terraform/` の中身を `004-user-data-nginx/terraform/` にコピーする
2. EC2インスタンスの `user_data` に、パッケージ更新・nginxインストール・nginx起動・自動起動有効化を行うシェルスクリプトを書く
3. `terraform apply` する（`user_data` を変更した場合、インスタンスが再作成されることがある点に注意）
4. インスタンス起動後、数十秒〜数分待ってから（起動処理の完了を待つ）、パブリックIPに対して `curl` でHTTPアクセスし、レスポンスが返ることを確認する
5. 応答がない場合は、AWSコンソールの「システムログを取得」機能や `user_data` のログ（`/var/log/cloud-init-output.log` など）を調べるとよい

## 要件（Must）

- [ ] EC2インスタンスを1台起動し `running` 状態であること、かつセキュリティグループがTCP80番のみを許可してEC2インスタンスに紐付いていること（`003-security-group` の内容を引き続き維持する）
- [ ] インスタンスの80番ポートにHTTPアクセスすると、何らかのレスポンス（2xx/3xx系）が返ること（`user_data` でHTTPサーバーが自動起動していることの確認を兼ねる）

## 制約（禁止事項）

- インバウンドルールに80番以外のポートを追加しないこと（動作確認にSSHログインは使わない設計とする）
- 使用可能なAWSサービスはEC2（デフォルトVPCの利用を含む）・セキュリティグループに限定する

## 推奨（Should）

- `user_data` はヒアドキュメント（`<<-EOF` など）でまとめて書き、可読性を保つ
- `Name` タグを引き続き付けておく（例: `Name = "dojo-shiro-ec2"`）。まだ `terraform output` を使わないため、テスト実行時にタグで検索すると探しやすい
- nginxのデフォルトページのままでよいが、余裕があれば `index.html` を上書きして「動いていることが分かるメッセージ」を表示させてもよい（任意）

## 受入テスト

`tests/acceptance.sh` を参照。概要は以下の通り。`terraform output` は未定義のため、`terraform apply` 後に自分でインスタンスID・セキュリティグループID・パブリックIPを確認し、環境変数として渡して実行する。

| # | 検証内容 | コマンド例 | 期待結果 |
|---|---|---|---|
| 1 | インスタンスが `running` 状態であり、セキュリティグループが80番のみを許可して紐付いている | `aws ec2 describe-instances` / `aws ec2 describe-security-groups` | `State.Name` = `running`、SG紐付けあり、80番の許可ルールが1件以上かつ80番以外の許可ルールが0件 |
| 2 | HTTPアクセスで応答が返る | `curl -o /dev/null -w "%{http_code}"` | HTTPステータスコードが2xx系または3xx系 |

## スコープ外

- `terraform output`（`005-outputs` で扱う）
- HTTPS化（ACM証明書の取得・設定）
- 送信元IPを絞り込む設計（`006-restrict-source-ip` 以降で扱う）
- ALB・Auto Scaling Group・複数AZ構成（今後のお題で扱う）
