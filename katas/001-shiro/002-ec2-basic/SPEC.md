# 001-shiro / 002-ec2-basic: EC2インスタンスを踏み台経由でのみアクセス可能にする

## 背景・目的

001-ec2-hello で「EC2を起動してTerraformでリソースを作る」感覚は掴めたはずである。本お題ではその上に、「最小権限の原則」をネットワークレベルで実践する。実務でEC2インスタンスを構築する際、SSHやHTTPのポートをインターネット全体（`0.0.0.0/0`）に開放してしまう事故は非常に多い。単一のEC2インスタンスとそれを保護するセキュリティグループの設計を通じて、送信元を必要最小限に絞り込む設計を学ぶ。

具体的には、管理用の踏み台サーバー（bastion）を1台用意し、対象のWebサーバー用EC2インスタンスへのSSH（22番）・HTTP（80番）アクセスを、踏み台サーバーのIPアドレスからのみ許可する構成を作る。

## 要件（Must）

- [ ] EC2インスタンスを1台起動する（対象サーバー。以下「Webサーバー」と呼ぶ）
- [ ] 踏み台サーバーとして使用するEC2インスタンス、または踏み台サーバーの固定IPアドレス（Elastic IPなど）を1つ用意する
- [ ] Webサーバー用のセキュリティグループを作成し、インバウンドルールは以下のみを許可する
  - TCP 22番（SSH）: 送信元は踏み台サーバーのIPアドレス（`/32`）のみ
  - TCP 80番（HTTP）: 送信元は踏み台サーバーのIPアドレス（`/32`）のみ
- [ ] インバウンドルールに `0.0.0.0/0` または `::/0` を送信元とする許可設定が一つも存在しないこと
- [ ] Webサーバー上でHTTPサーバー（nginx、Apacheなど）が起動し、80番ポートで何らかのレスポンス（2xx/3xx等）を返すこと
- [ ] 踏み台サーバーからWebサーバーへSSH接続が成功すること
- [ ] 踏み台サーバーからWebサーバーへHTTP（curlなど）で疎通できること
- [ ] 踏み台サーバー以外のIPアドレスからは、Webサーバーの22番・80番ポートへの接続が失敗する（タイムアウトまたは明示的な拒否）こと
- [ ] `terraform output` で、少なくとも以下の値を出力すること（受入テストが参照するため）
  - WebサーバーのインスタンスID
  - Webサーバーの（パブリックまたは到達可能な）IPアドレス
  - Webサーバー用セキュリティグループのID

## 制約（禁止事項）

- インバウンドルールの送信元に `0.0.0.0/0` または `::/0` を指定しないこと（SSH・HTTPともに）
- Webサーバー用セキュリティグループに、22番・80番以外の不要なポートを開放しないこと
- 踏み台サーバー自身のセキュリティグループも、SSH（22番）の送信元を無制限にしないこと（自分の作業用グローバルIPなど、検証可能な範囲に限定する。`/32`を推奨）
- IAMロール・IAMユーザーを作成する場合、`*` を使った過剰な権限を付与しないこと
- 使用可能なAWSサービスは EC2 / VPC（デフォルトVPCで可）/ セキュリティグループ / Elastic IP（任意）に限定する。ALBやAuto Scaling Groupは範囲外（黄帯で扱う）

## 推奨（Should）

- リソース名には `dojo-shiro01-` などのプレフィックスを付け、他のお題のリソースと区別できるようにする
- タグ付けを行う（例: `Project=aws-terraform-dojo`, `Kata=shiro-01`, `ManagedBy=terraform`）
- セキュリティグループのルールには `description` を設定し、許可理由を明記する
- 踏み台IPやAMI IDなどの環境依存値は変数（`variables.tf`）に切り出し、ハードコードを避ける
- `outputs.tf` に、受入テストが必要とする値をまとめて出力する

## 受入テスト

`tests/acceptance.sh` を参照。概要は以下の通り。

| # | 検証内容 | 方法 | 期待結果 |
|---|---|---|---|
| 1 | Webサーバーが running 状態である | `aws ec2 describe-instances` | `State.Name` = `running` |
| 2 | セキュリティグループのインバウンドルールに全開放が存在しない | `aws ec2 describe-security-groups` | `0.0.0.0/0` / `::/0` を送信元とする許可ルールが0件 |
| 3 | 22番・80番の送信元が踏み台IPの `/32` に限定されている | `aws ec2 describe-security-groups` | 許可CIDRが踏み台IPの`/32`のみ |
| 4 | 踏み台サーバーからSSH接続できる | 踏み台上（または踏み台経由）で `ssh` 実行 | 接続成功（exit code 0） |
| 5 | 踏み台サーバーからHTTPアクセスできる | 踏み台上（または踏み台経由）で `curl` 実行 | HTTPステータスコードが2xx系または3xx系 |
| 6 | 踏み台以外からはSSH/HTTPともに到達できない | 踏み台以外の環境から `nc` / `curl` でタイムアウト検証 | 一定時間内に接続が確立しない |

具体的な実行手順・コマンドは `tests/acceptance.sh` の雛形を参照し、自分の実装（`terraform output` の項目名など）に合わせて埋めること。

## スコープ外

- ALB・Auto Scaling Group・複数AZ構成（黄帯で扱う）
- モジュール化・tfvars分離・リモートステート（茶帯で扱う）
- HTTPS化（ACM証明書の取得・設定）
- WAFやNetwork ACLによる追加の防御層
- 踏み台サーバー自体の堅牢化（多要素認証、Session Managerへの置き換えなど）
