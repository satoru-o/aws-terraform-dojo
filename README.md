# aws-terraform-dojo

AWS Terraformを**生成AIに書かせず、自分の手で実装する**ための学習用リポジトリ（道場）です。

## 道場のコンセプト

生成AIにコードを書かせれば、動くTerraformはすぐに手に入ります。しかし「なぜこのリソース構成が必要なのか」「なぜこの書き方をするのか」という設計判断の力は、実際に手を動かして詰まった経験からしか身につきません。

このリポジトリでは、Claude Codeに以下の3つだけを担当させ、**Terraformの実装コード（`.tf`ファイルの中身）は一切書かせません**。

1. リポジトリ構造とドキュメントの整備
2. 各お題の「仕様書」（SPEC.md）の作成
3. 完成後の受入テスト結果に対するレビュー支援

仕様書を読み、手を動かし、詰まり、調べ、直す——このサイクルを踏むことが道場の目的です。

## 段位制度

| 段位 | テーマ | 内容 |
|---|---|---|
| 白帯 (001-shiro) | 単一リソース中心 | EC2 + SGなど、基本的なリソースを単体で組む |
| 黄帯 (002-ki) | 複数リソースの依存関係 | ALB + ASG + 複数AZなど、リソース間の依存・参照を扱う |
| 茶帯 (003-cha) | モジュール化・状態管理 | モジュール分割、tfvars分離、リモートステート |
| 黒帯 (004-kuro) | 組織レベルの設計 | マルチアカウント、IAMロール委譲、コスト制約付き設計 |

段位フォルダ・お題フォルダともに `001`、`002`、`003`... という3桁ゼロ埋めの番号プレフィックスを付け、
アルファベット順ソートがそのまま段位順・お題順になるようにしています。段位が5個・10個に増えても、
お題が100個を超えても並び順が崩れません。

## リポジトリ構成

```
aws-terraform-dojo/
├── README.md              # このファイル
├── katas/                 # お題（型）
│   ├── 001-shiro/             # 白帯
│   │   └── 001-ec2-basic/
│   ├── 002-ki/                # 黄帯
│   │   └── 001-alb-asg/
│   ├── 003-cha/               # 茶帯
│   │   └── 001-multi-module/
│   └── 004-kuro/              # 黒帯（お題は未作成）
├── templates/
│   └── SPEC_TEMPLATE.md   # 仕様書のテンプレート
└── docs/
    └── review-checklist.md  # レビュー観点まとめ
```

各お題ディレクトリの構成は共通です。

```
katas/<帯番号>-<帯名>/<お題番号>-<お題名>/
├── SPEC.md         # 仕様書（要件・制約・受入テストを定義）
├── terraform/      # ここに自分の手でTerraformコードを実装する（空、.gitkeepのみ）
└── tests/
    └── acceptance.sh   # 受入テストの雛形
```

## お題の進め方

1. `katas/<帯番号>-<帯名>/<お題番号>-<お題名>/SPEC.md` を読む
2. `SPEC.md`の「要件（Must）」「制約（禁止事項）」を理解した上で、`terraform/` 配下に**自分の手で**Terraformコードを実装する（生成AIによるコード生成は使わない）
3. `terraform plan` / `terraform apply` の後、`tests/acceptance.sh` を実行して自己採点する
4. 実行結果を持ってClaude Codeにレビューを依頼する

## レビュー依頼時のプロンプト例

```
katas/001-shiro/001-ec2-basic の受入テストを実施しました。
以下が terraform plan の出力と acceptance.sh の実行結果です。
SPEC.md のMust要件を満たしているか判定してください。

--- terraform plan の出力 ---
(ここに貼る)

--- acceptance.sh の実行結果 ---
(ここに貼る)
```

Claude Codeは実装コードを書き直すのではなく、`docs/review-checklist.md` の観点に沿って、SPEC.mdの要件に対する充足性判定と改善のためのフィードバックのみを行います。

## 新しいお題を追加する場合

`templates/SPEC_TEMPLATE.md` をコピーして、`katas/<帯番号>-<帯名>/<お題番号>-<お題名>/SPEC.md` として作成してください。
番号は同じ帯の中で連番（`001`, `002`, ...）を、3桁ゼロ埋めで付けてください。
